# Zeta Accessibility Reader

이 폴더가 실제 **외부 Android 앱** 프로젝트입니다. Python/ADB 수집기가 아니라 휴대폰 안에서 실행되는 `AccessibilityService`가 제타 화면을 직접 읽습니다.

## 동작 순서

1. 앱을 설치하고 `접근성 설정 열기`를 누릅니다.
2. Android 설정에서 `제타 대화 읽기` 서비스를 사용 설정합니다.
3. 앱의 `제타 열기` 버튼으로 제타 채팅방에 들어갑니다.
4. 서비스가 `com.scatterlab.messenger`의 화면 변경 이벤트만 받습니다.
5. 메시지를 `내 응답`, `내 서술`, `AI 대사`, 화자별 `인물 서술`, `배경 설명` 구간으로 나눠 대화방별 현재 상태에 병합합니다.
6. 최신 AI 답변처럼 아직 ID가 없는 응답은 하나의 임시 턴에서 계속 갱신하고, 다음 사용자 메시지 뒤에 ID가 생기면 같은 턴으로 확정합니다.
7. A/B/C 대화방을 오가면 캐릭터 이름이 아니라 보이는 정식 메시지 ID와 기존 상태의 교집합으로 방을 다시 찾습니다. 최근 사용한 대화방 10개만 유지합니다.
8. 방마다 현재 상태 파일 하나만 갱신합니다. 별도의 방문 파일이나 과거 분기 사본은 만들지 않습니다.
9. 기존 응답을 수정하거나 과거 지점에서 새 흐름을 시작하면 그 지점 뒤의 이전 흐름은 삭제합니다. 단순 스크롤이나 화면 밖 이동은 삭제로 판단하지 않습니다.
10. 마지막 실제 내용 변경 뒤 3시간 동안 새 내용이 없으면 기존 내용은 JEV 기준선으로만 등록합니다. 앱을 오가거나 Reader를 여는 동작은 이 시간을 바꾸지 않습니다. 이후 새 정식 `USER RESPONSE`부터 새 분석을 시작합니다.
11. 5초간 안정된 JEV 범위를 휴대폰에서 TypeSafe API로 직접 보내고 관찰값만 표시합니다. 자동 종료나 개입은 아직 하지 않습니다.

제타 화면의 `실시간 읽기` 오버레이를 5초간 계속 누르면 Reader가 열리고 현재 대화 상태가 표시됩니다. 기존 내용과 새 JEV 분석 범위 사이에는 기준선이 표시되므로 실제 전송 범위를 직접 확인할 수 있습니다. 손을 떼면 열기가 취소됩니다.

## 핵심 파일

- `ZetaAccessibilityService.kt`: 제타 이벤트 수신, 화면 트리 복사, 시간 측정
- `ZetaDialogueParser.kt`: 발화자·본문·내 응답/AI 응답 분류
- `ConversationState.kt`: 대화방 분리, 메시지 병합, JEV용 턴과 revision 생성
- `ConversationStatePersistence.kt`: 대화방별 현재 상태를 앱 재시작 뒤에도 복원
- `CaptureStore.kt`: 현재 대화방 선택과 상태 저장
- `JevEvaluationCoordinator.kt`: 최신 revision 전송, 오래된 응답 폐기, 관찰값 표시 상태 관리
- `MainActivity.kt`: 권한 상태와 결과를 화면에 표시
- `res/xml/zeta_accessibility_service.xml`: 제타 패키지만 접근하도록 제한

## 측정값

- **화면 트리 분석 시간**: `rootInActiveWindow`를 읽기 시작해서 분류가 끝날 때까지
- **변화 감지/저장 시간**: 접근성 이벤트가 있으면 이벤트부터 저장까지, 이벤트가 없으면 500ms 폴링을 기준으로 한 최대 예상 시간

React Native가 접근성 이벤트를 빠뜨리는 경우에 대비해 제타가 전면에 있는 동안 500ms 간격으로도 화면을 확인합니다.

## 휴대폰 JEV 직접 연결

Reader 화면의 `TypeSafe API 키 저장/교체`에서 개인 API 키를 한 번 입력합니다. 키는 APK나 일반 설정 파일에 넣지 않고, Android Keystore가 만든 기기 전용 암호화 키로 보호해 앱 내부 저장소에 보관합니다. 저장된 원문 키는 화면에 다시 표시하지 않습니다.

앱은 `https://api.typesafe.ai/v1/systemone`에 직접 HTTPS 요청합니다. 컴퓨터, USB, 로컬 브리지, `adb reverse`는 필요하지 않습니다. 요청에는 방 전체 기록이 아니라 현재 분석 기준의 `USER RESPONSE`부터의 턴만 들어갑니다. 마지막 내용 변경 뒤 3시간 안에 대화가 이어지면 기존 기준선 이후의 모든 턴을 계속 포함합니다.

키를 교체했거나 일시적인 오류가 있었다면 `현재 JEV 범위 다시 분석`을 눌러 새 메시지 없이 같은 범위를 다시 요청할 수 있습니다.

디버그 빌드에는 데이터셋 실험용 한국어 입력 통로가 있습니다. ADB shell의 `DUMP` 권한으로 호출할 때만 현재 제타 채팅의 입력칸을 채우고 전송합니다. 일반 앱과 릴리스 빌드에서는 이 통로를 사용할 수 없습니다.

## 저장 위치

대화방별 현재 상태는 `files/conversations/*.conversation`에 방마다 하나씩 저장합니다. 최근 사용한 방 10개만 유지하며, 방을 다시 방문해도 새 파일을 만들지 않고 같은 파일의 현재 메시지와 시간만 갱신합니다. 이전 버전에서 만들었던 방문 기록과 `latest_capture.txt`는 자동으로 삭제합니다.

하나의 AI 메시지 안에서 화자가 바뀌면 화자별 대사와 배경 설명을 순서대로 분리합니다. 같은 메시지 ID의 현재 구간만 유지하고, ID가 없는 최신 AI 답변의 수정·재생성은 과거 버전을 쌓지 않고 같은 임시 턴을 덮어씁니다. 과거 지점에서 새 흐름이 확인되면 기존 뒷부분은 남기지 않습니다. revision은 역할과 현재 본문 순서로 계산하므로 임시 AI 턴에 정식 ID만 붙는 경우에는 바뀌지 않습니다. 다른 앱은 이 파일에 접근할 수 없습니다.

## 중요한 Android 제한

- 접근성 권한은 앱이 스스로 켤 수 없고 사용자가 Android 설정에서 직접 허용해야 합니다.
- 제타가 실제로 화면에 렌더링한 접근성 노드만 읽을 수 있습니다.
- 화면에 아직 로드되지 않은 오래된 메시지는 자동으로 위로 스크롤하지 않는 한 읽히지 않습니다.
